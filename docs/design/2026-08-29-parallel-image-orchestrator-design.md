# Parallel Image Orchestrator 设计

状态：DRAFT，待 YJ 审阅
创建日期：2026-08-29
适用范围：本项目的批量视觉资产生产；可安装为其他 Codex 用户可复用的本机套件。

## 1. 要解决的问题

Codex 在同一对话中多次原生生图可能出现重连或不可用。对于一组 4 张及以上、数量不固定的图片，用户需要先在 Codex 中依据项目规范生成并确认逐图提示词；确认后，将任务自动分配给 Codex 与同一台电脑已登录的 ChatGPT 网页端并发执行，结果自动进入用户指定目录，并保留可恢复的任务记录。

这不是把全部任务转交网页端。它是两个生成通道的并行调度：默认每个通道最多 5 个活动任务。任务总量可能为 4、10、20 或更多；不超过 3 张时不启动分发。

## 2. 目标与非目标

### 目标

- 提供可安装的 `parallel-image-orchestrator` Skill 套件，而非只依赖某个项目的固定路径。
- 从项目规则、视觉方案和人物母版中形成逐图提示词，先展示完整任务清单并等待人工一次确认。
- 按负载均衡自动分配任务；网页端与 Codex 端各最多 5 个活动任务。
- 网页端每张图使用 ChatGPT Project 内一个独立的新对话，避免提示词互相污染。
- 网页端图片与 Codex 原生图片以同一命名规则和清单归档到本批次目标目录。
- 进程或网络中断后可从 `manifest.json` 恢复，不重复已完成图片。
- 不读取、导出、写入或保存浏览器 Cookie、密码、令牌或聊天历史。

### 非目标

- 不替用户创建、分享或修改 ChatGPT Project 的长期规范；首次安装向导只检查其存在并要求用户选择。
- 不自动公开发布图片、文章或社交媒体内容。
- 不保证绕过账号限额、验证码、风控、登录失效或 ChatGPT 网页界面变化。
- 不把 ChatGPT Project 的固定指令复制进每条变量提示词；固定规范由用户预先上传和维护。
- 不把 API 作为默认生成通道，也不要求或保存 OpenAI API Key。

## 3. 方案比较与采用方案

### A. Skill + Chrome 扩展 + 本机归档桥接（采用）

Skill 负责规范解读、提示词、确认和任务清单；扩展负责网页任务页准备；本机桥接负责队列、落盘和恢复。它符合“安装完成后，一次确认即可批量准备网页任务，用户只在网页端完成发送确认”的目标；任务页映射、状态和后续归档仍由本机记录管理。

代价是首次需要安装扩展和本机桥接组件，并授权扩展访问 `chatgpt.com`、标签页与下载事件。网页 DOM 变化需要版本化适配器和降级提示。

### B. Skill + 浏览器半自动操作

Skill 打开任务页并批量填入内容，但用户分别发送。它牺牲最后一步的全自动换取对网页风控、登录和 UI 变化的可控性，作为当前网页通道的实际边界。

### C. API 任务队列

本地程序直接调用图像 API，最利于并发与归档，但需要 API Key 并产生独立计费；也不使用用户已有的 ChatGPT 网页 Project。作为未来可选通道，不纳入第一版。

## 4. 组件与职责

```text
项目规范 / 当前视觉方案 / 人物母版 / 用户指定 Markdown 提示词目录
                 │
                 ▼
       Codex Skill：提示词与确认
                 │  已确认 manifest
                 ▼
       本机调度器（队列、状态、归档）
          ┌──────┴──────┐
          ▼             ▼
  Codex 任务执行器     Chrome 扩展
  （最多 5 个）        （最多 5 个独立 Project 对话）
          └──────┬──────┘
                 ▼
  本批次目标目录：图片、manifest、提示词、运行日志
```

### Skill

- 读取当前项目的正式稿、已确认视觉方案及其引用资源；对本项目出现 YJ 角色时，强制带入 `05视觉规范/protrait.png` 作为人物一致性依据。
- 生成每张图的 `task_id`、用途、渠道无关的完整提示词、参考图角色、比例、文件基名和约束。
- 接受用户指定的提示词目录或单个 Markdown 文件；支持 `001.md` 这类按文件编号，或 `## 001` 这类按章节编号。目录缺失、映射不明确或提示词为空时停止，不扫描整个项目猜测来源。
- 在创建批次前读取 Markdown，将完整提示词和 `prompt_source`（来源路径、章节和哈希）写入任务记录，并向用户单独报告扩展载入路径和图片归档路径。
- 当任务数大于 3 时生成待确认预览；未获得用户明确确认不得启动调度器。
- 把确认后的任务写入用户选择的批次根目录下的新批次目录。不得覆盖旧批次。

### 本机调度器

- 为一次运行创建唯一 `batch_id`，并记录用户选择的批次根目录与 ChatGPT Project 配置名；未设置时默认当前对话/项目文件夹，并在输出中明确说明。
- 按活动数最少的通道分配任务；开始时平衡两边，后续任一通道完成后优先在该通道补位。任务本身不因“网页”或“Codex”具有固定归属。
- 维护 `queued`、`dispatching`、`generating`、`downloaded`、`archived`、`retryable_failure`、`blocked`、`failed` 状态。
- 对网页端发送调度器为每个任务解析出的完整提示词；固定视觉规范仍由目标 Project 的项目指令与来源文件提供，扩展不复制这些共享资料。提示词可以来自任务对应的 `.md` 文件，但应在创建批次前由 Skill/调度器读取并写入任务记录。
- 发现登录失效、验证码、额度或无法识别页面时，将对应任务置为 `blocked`，停止该任务并请求用户接管；不绕过验证。网页结果观察限定最新助手生图轮次并按生图容器去重；若新版页面没有 Download/Save 控件，只对唯一的 HTTPS 生图地址发起一次受控下载。由旧版观察器造成的可恢复阻塞可在载入批次时自动恢复一次，不重发提示词。

### Chrome 扩展

- 仅在用户选择的、已登录的 ChatGPT Project 中工作。
- 扩展选项页只要求用户粘贴包含 `manifest.json` 的当前批次目录。提示词来源目录、批次根目录和 `图片/` 归档子目录都不应填入该字段。
- 每张网页任务开启独立标签页或独立 Project 对话，上传该任务声明的参考图并批量填入完整任务提示词；填入后回读可见输入框，只向扩展页面报告“已载入/未载入”，不铺开展示长 Markdown 正文；最终发送由用户在网页端确认。
- 通过页面状态判断生成完成；每个网页任务默认追加“只生成 1 张图片”的约束，并且只有在最新 assistant turn 中识别到唯一结果和唯一可用的 Download/Save 控件时，才触发页面官方下载动作，不调用未公开的 ChatGPT 后端接口。
- 使用下载事件将临时下载与 `task_id` 关联，交给本机桥接归档。
- 下载完成先原子记录 `completed` 并释放同通道排队任务，再执行归档；新释放的网页任务只预备和填入，不代替用户点击发送。
- 不访问 Cookie、localStorage、密码管理器或非必要页面数据。

### 本机归档桥接

- 以用户在运行前选择的目标目录为唯一写入根目录；所有输出只写入该目录下新建的 `图片批次_<batch_id>`。
- 将 Chrome 下载完成文件及 Codex 原生生成后的文件复制或移动为统一的版本化名称。
- Codex 原生图片首先位于 Codex 默认生成目录；执行器在成功后只复制已选定结果到批次目录，保留源文件并避免覆盖。

## 5. 调度规则

| 总任务数 | 行为 |
|---:|---|
| 1–3 | 不启动分发；只交付确认后的提示词包。 |
| 4–10 | 在 Codex 与网页端尽量均分，且每侧不超过 5 个活动任务。 |
| 11+ | 初始最多 Codex 5 + 网页 5；后续由先释放的通道领取下一条排队任务。 |

同一时刻每通道活动数不得超过 5。任务完成、取消、明确失败或转为 `blocked` 才释放槽位。重试采用指数退避并有最大次数；验证码、登录与策略限制不自动重试。

## 6. 批次数据与命名

每次确认创建：

```text
<用户选择的目标目录>/图片批次_<batch_id>/
├── manifest.json
├── prompts.md
├── events.jsonl
├── 参考图/
└── 图片/
    ├── 001_codex_封面主视觉_v01.png
    └── 002_web_任务链_v01.png
```

路径语义必须保持分离：提示词来源目录是 Skill 的输入；批次根目录是创建 `图片批次_<batch_id>` 的父目录；当前批次目录是扩展载入路径；`图片/` 是最终归档目录。扩展不得直接读取提示词来源目录。

`manifest.json` 是唯一任务状态源。每个任务至少包含：`task_id`、用途、完整提示词摘要、变量提示词、网页实际使用的 `effective_prompt`（含单图约束）、可选的 Markdown 来源路径/哈希、参考图相对路径、比例、原始分配、当前通道、状态、尝试次数、生成时间、下载文件、归档文件、失败原因及复现提示。来源元数据用于追溯，不要求扩展在运行时读取 `.md`。

图像文件格式为：`<三位序号>_<实际通道>_<安全文件名>_v<两位版本>.<ext>`。重做创建新版本，不覆盖既有结果。

## 7. 首次安装与日常使用

### 首次安装

1. 安装 Skill、浏览器扩展和签名的本机桥接组件。
2. 在 Chrome 中授予扩展 `chatgpt.com`、标签页与下载权限。
3. 用户登录 ChatGPT，并自行创建或选择一个存放固定视觉规范的 Project。
4. 向导保存 Project 的公开页面定位信息与本地配置名，不保存会话凭据。
5. 执行只读连接检查和一次不发送的任务预检；确认网页元素、下载监控和目标目录写入权限均可用。

### 日常使用

1. 用户在 Codex 请求一批视觉资产，并提供提示词来源目录（如有）和批次根目录。
2. Skill 依据当前项目材料读取 Markdown、生成或核对任务清单和逐图提示词。
3. Skill 创建批次并输出扩展载入路径；用户把该完整路径粘贴到扩展，而不是粘贴提示词目录。
4. 用户明确“确认分发”，调度器启动双通道队列；网页任务页由扩展批量创建/修复并填入，用户只在网页端完成每页发送确认。
5. 完成后 Skill 汇总结果、失败项与图片归档路径，供人工验收或下一轮定向修改。

## 8. Codex 通道的可行性门禁

网页通道可由扩展接管。Codex 原生生图是否能从本机调度器可靠创建 5 个独立任务，取决于当时 Codex Desktop 可用的任务创建与图片生成能力，不能只凭 Skill 指令假定成立。

因此第一版必须包含环境探针：在不创建真实图片前检查是否能创建隔离任务、将每项任务带入原生图片工具、获得本地结果路径，并把结果回传 `manifest`。探针失败时，套件将 Codex 通道标记为不可用，网页通道仍按其自身上限运行，并显示明确原因；绝不虚报 5 路 Codex 并发。

## 9. 故障与恢复

- Codex 当前对话重连或关闭：已交给网页扩展的任务继续运行；本机调度器继续记录下载事件。恢复后读取 `manifest.json`，不重发 `archived` 项。
- Chrome 重启或扩展失联：任务页映射按批次版本校验；保存的 tab ID 失效时，先按已保存的对话 URL 或页面中唯一的提示词自动重绑现有任务页，只有无法安全匹配时才在下一次“创建 / 修复网页任务页”时替换，不把原始 `No tab with id` 暴露给用户。
- 图片生成完成但下载失败：任务保留网页对话定位信息，后台只重试已发生的下载/归档阶段，不重新生成；如果下载被中断或结果无法唯一识别，则将任务标为 `blocked` 并显示原因。用户可以使用“恢复阻塞的网页监控（不重发）”重新挂载监控，不会再次发送提示词。
- 网页任务准备阶段发生提示词回读不一致、旧页面映射冲突或重复草稿：扩展先选择实际渲染的可见编辑器并逐页验证；若页面重绘导致 CDP 文本输入没有落地，则用一次替换式页面输入事件路径重试并报告具体失败任务。仍失败时提供“重置当前批次网页准备（不删除图片/对话）”，只把尚未发送的网页任务恢复为 `queued`，清除扩展本地页面映射与监控残留，并保护已发送、生成中和已归档任务。旧标签页由用户自行关闭，避免误关其他对话。
- 网页 UI 更新：适配器无法定位控件时立即停止投递，写入诊断信息，并要求更新扩展；不盲点、不过度重试。
- 某通道不可用：已确认任务按配置可暂停或转移至另一个通道；自动转移前在本批次确认页面明确显示，默认不跨通道重做已开始任务。

## 10. 验收标准

- 2 张任务只生成提示词包，无浏览器任务、无 Codex 分发。
- 10 张任务经一次确认后，能建立最多网页 5、Codex 5 个独立活动任务，且清单状态与实际结果一致。
- 20 张任务从队列补位，任一通道活动数不超过 5；已完成文件不被覆盖。
- 每个完成任务在目标目录存在一张对应的版本化图片、提示词记录与状态记录。
- 关闭或重连 Codex 当前对话后，网页端已投递任务仍可下载并被归档。
- 登录、验证码、限额、网页结构变化和写入失败均能清晰报告，且不会保存凭据或伪造成功状态。
- 以本项目视觉任务验证时，人物任务引用 `05视觉规范/protrait.png`，固定规范与本轮变量提示词均可追溯。

## 11. 实施边界

实现前需要先验证 Codex Desktop 的可编程任务并发能力。若它不支持真正的本机后台原生生图，第一版仍可交付网页端最多 5 路的批量任务页准备与统一归档，但最终发送由用户确认；Codex 通道只能降级为由当前 Codex 会话逐项执行，或在用户另行授权 API 后改为 API 通道。该限制必须在安装向导和每批次确认页明确显示。
